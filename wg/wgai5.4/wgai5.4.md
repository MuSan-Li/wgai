WGAI 迎来了新一轮版本升级。

- 新增 绿幕实时抠像，数字人可透明叠在页面上
- 新增 对外接口文档 + 可直接打开的接入 Demo
- 优化 语音合成速度，模型常驻不再重复加载

持续让 WGAI 成为 **AI视觉 + 智能机器人 + 数字人交互平台**

# 🔥 核心升级一：仿真数字人形象配置

本次版本正式支持 **自定义数字人形象**。

上传一段本人出镜的视频，系统离线完成一次预处理，之后即可长期复用：

- 人脸关键点提取
- 口型驱动底板缓存
- 形象多版本管理
- 静置（待机）画面配置

实现：

> 用自己的形象，说自己想说的话

不说话时循环播放待机画面，收到文本后自动切换成说话画面，说完自动回到待机，**整条视频流全程不中断**。

---

# ⚡ 核心升级二：文本驱动实时口型

发送一段文字，系统自动完成：

- 文本切句
- 语音合成
- 口型驱动
- 视频编码推流
- 前端播放

口型与声音严格对齐，不是循环播放的假动作。

## 💡 语音合成提速

旧实现每次合成都要重新加载一次语音模型，上百 MB 的模型反复读盘、反复初始化，**每句话白白多花 1~3 秒**。

本次改为**模型常驻内存**，只在服务启动时加载一次：

- 首次合成：正常加载
- 后续合成：**毫秒级响应**

同一个模型换一个音色编号就能切男声 / 女声，**不需要换模型**。

# 🎯 核心升级三：边生成边播 · 首句秒开

这是本次版本体验提升最明显的一处。

## 问题

一整段 16 秒的文字，如果等全部合成完再播，用户要盯着屏幕**等十几秒**才听到第一个字，会以为"点了没反应"。

## 做法

把长文本按标点切成多句，**第一句合成完就立刻开播**，后面几句在播放期间陆续生成：

```
整段：  [————————16秒————————]     首帧要等十几秒
切句：  [3秒][4秒][3秒][3秒][3秒]   首句 1~2 秒就开口
```

## ⚠ 关键难点：不能播到一半断

生成速度会波动（显卡被其他任务占用、句子长短不一），一旦播放追上生成进度，画面就会跳回待机、声音断掉 —— 比多等几秒难受得多。

本次采用**自适应预缓冲**：

- 一边生成一边测量真实生成速度
- 实时计算"现在开播会不会断"
- 生成够快就立刻开播；偏慢就自动多等一会
- **算出来不够时宁可多等，也绝不强行开播**

不需要人工调参，速度快慢都能保证播放连贯。

## 📝 两种播报模式

| | 切句模式（默认） | 不切句模式 |
| --- | --- | --- |
| 处理方式 | 按标点切成多句 | 整段作为一句 |
| 多久开口 | **1~2 秒** | 要等整段合成完 |
| 进度事件 | 每句各一次，可细粒度联动 | 只在开头 / 结尾各一次 |
| 适合场景 | 长文本播报、需要按句联动页面 | 短句、要求原文一字不动 |

前端一个开关即可切换，接口层面就是一个 `split` 参数。

# 📡 核心升级四：播报进度实时回传

播报过程中，前端会实时收到"**现在读到第几句**"，可据此驱动页面：

- 切换图表
- 高亮区域
- 显示字幕
- 触发任意业务动作

事件内容包含句子序号、总句数、句子原文。

## ⚠ 为什么不能前端自己按时长估算

从提交文本到画面出声，中间隔着生成排队、视频编码、推流传输、流媒体转封装、播放器缓冲，**每一段延迟都不固定**。按音频时长推算进度，会越播越偏，播到后面能差好几秒。

本次实现由**驱动层在帧真正推出去的那一刻上报**，从源头保证准确。

链路上还做了两处加固：

- **断线自动重连**，并补发断开期间漏掉的事件，网络抖动不丢消息
- **心跳保活**，避免空闲长连接被中间设备静默掐断

# 🎨 核心升级五：绿幕实时抠像

数字人视频流采用绿幕拍摄，**在浏览器端用 WebGL 实时抠像**，可以透明地"站"在页面上，而不是一块带绿底的方块视频。

支持实时调节：

- 绿幕颜色
- 抠像阈值
- 边缘柔化
- 去绿边
- 边缘收缩

背景可任意替换：纯色、图片、视频，或完全透明叠在现有页面内容之上。

# 🔌 核心升级六：对外接口 + 接入 Demo

本次同步提供完整的第三方接入能力：

- **接口文档**：调用流程、参数说明、事件格式、常见问题排查表
- **接入 Demo**：单个 HTML 文件，双击即可打开测试，包含连接、播报、事件联动、抠像参数面板、背景切换

第三方只需对接一个服务地址，拿到「声音 ID + 音色编号 + 拉流地址」即可接入，无需了解内部实现。
